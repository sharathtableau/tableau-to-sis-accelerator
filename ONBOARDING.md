# Onboarding — setup steps

> ### 👉 Read `START_HERE.md` FIRST.
> This file is **setup mechanics only** — clone, install, build, run the tests.
> It assumes you already know what the project does and what words like *IR*,
> *gate*, *sheet* and *extract* mean. `START_HERE.md` explains all of that in

## 1. Get access

The repo is **private**: `github.com/sharathtableau/tableau-to-sis-accelerator`

Sharath adds you at **Settings → Collaborators → Add people**. You'll get an
email invite; accept it before cloning.

## 2. Clone — IMPORTANT: use a SHORT path on Windows

This repo has paths up to **112 characters** deep (the validation-reference
evidence folders). Windows caps total path length at 260, so **cloning into a
deeply nested folder fails** with `Filename too long` and you get a broken,
partial checkout.

**Clone somewhere short.** `C:\dev\` is ideal:

```bash
git clone https://github.com/sharathtableau/tableau-to-sis-accelerator.git C:/dev/tsis
```

Rule of thumb: your clone directory must be **under ~147 characters**. Do NOT
clone into a long path like `C:\Users\<you>\Downloads\Some Long Project Name\...`.

Belt and braces — enable long-path support once, globally:

```bash
git config --global core.longpaths true
```

Verify you got a complete checkout (`git status` should be empty):

```bash
git status --short
```

If that prints anything, your checkout is incomplete — re-clone to a shorter path.

## 3. Environment

Python 3.10+. Dependencies are in `environment.yml`. Key ones: `streamlit`,
`altair`, `pandas`, `duckdb`, `snowflake-snowpark-python`, `tableauhyperapi`,
`playwright`, `scikit-image`, `vl-convert-python`, `fpdf2`, `requests`.

If you'll touch the screenshot path (Track B), you also need a browser:

```bash
python -m playwright install chromium
```

## 4. Build steps — REQUIRED before the first test run

Build output is not in the repo (it's all rebuilt from tracked source), but the
regression suite needs two pieces of it. **Run both of these once after
cloning**, or the suite fails partway with confusing errors.

**4a. Generate the Superstore app.** `test_app_interactions` renders
`app_superstore.py` headless. Without it the suite dies after 6 gates with
`FileNotFoundError: app_superstore.py`:

```bash
python codegen.py superstore_ir.json -o app_superstore.py
```

Prints `Generated app_superstore.py: 10 dashboards, 21 sheets`. Re-run any time
you change `codegen.py` or the IR.

**4b. Decode the whole test corpus.** Several gates query tables that live
inside the workbooks' bundled Tableau extracts. The decoded CSVs are gitignored
(~25 MB of derived data), so regenerate them from the tracked `.twbx` files.
Skip this and you get `CatalogException: Table with name ... does not exist`
partway through the run — from `test_ecommerce_end_to_end`,
`test_parity_validation`, and others.

Decode **all 12** corpus workbooks in one pass (Git Bash / WSL):

```bash
for w in Workbooks/*.twbx; do python init_workbook.py "$w"; done
```

PowerShell equivalent:

```bash
Get-ChildItem Workbooks/*.twbx | ForEach-Object { python init_workbook.py $_.FullName }
```

Takes a few minutes total. It decodes each extract to CSV under `data/` and
merges every datasource into `datasources.json`. **Needs `tableauhyperapi`
installed** — if that package won't install on your machine, ask Sharath for a
copy of the `data/` folder instead; nothing else in the setup depends on it.

## 5. Prove your setup — run the suite

```bash
python tests/test_regression.py
```

**This runs fully offline.** No Snowflake account, no Tableau credentials, no
network — it uses DuckDB locally plus fake Snowflake sessions. Expect
**82 gates** (81 auto-run + 1 deliberately manual that needs a live session).
It ends with `ALL REGRESSION TESTS PASSED`.

A few gates print `skip ... (workbook not present)` — that is normal and
expected; those reference workbooks that aren't in the repo.

**The suite must stay green.** Run it before you call anything done.

## 8. Branching — do not commit to `main`

Two people, one repo. Always branch:

```bash
git checkout -b track-a/bins
```

Naming: `track-a/<task>` or `track-b/<task>`, e.g. `track-b/global-sales-crash`.
Push your branch and open a PR; don't push to `main` directly.

**The one file both tracks can touch is `engine.py`.** Track A owns it. Track B
must flag it before editing (a caption/title change there alters the shipped
app's visuals, which is a product decision, not a validation side-effect).

## 9. The rules that matter most here

This project's value is that it is *trustworthy*, not that it's fast. Three
invariants; breaking one is worse than leaving a bug open:

1. **`BLOCKED` (never measured) and `FAIL` (proven wrong) must never look the
   same.** A missing proof cannot become a pass.
2. **Never guess.** Where the code refuses — an ambiguous crosstab, an
   unresolvable column, a multi-fact graph — that refusal *is* the feature. At
   least two refusals exist because a looser version was tried and found
   genuinely ambiguous against real data.
3. **Nothing is silently dropped.** Every unsupported construct produces a
   named finding, never a blank chart or a guessed number.

Every fix needs a regression gate with **proven teeth**: revert your fix and
confirm the gate goes red. A gate that passes either way is not a gate.

Update `status_config.json` and `MVP_ACCELERATOR_SCOPE.md` **in the same commit
as your change** — the trackers are hand-maintained and have drifted before.

## 10. Never commit secrets

Two live tokens have already leaked in this project's history (one GitHub PAT,
one Tableau PAT). GitHub's push protection caught the second one.

- Credentials come from **env vars** (`TABLEAU_PAT_NAME` / `TABLEAU_PAT_SECRET`),
  `getpass`, or Snowflake secret bindings — **never** a file.
- `tableau_server_sis_setup.sql` has a `<PASTE_YOUR_...>` placeholder. Fill it in
  a **local copy you never commit**.
- Never paste a token into a script, a config file, or a chat with an assistant.
